## 🇺🇸 English

### What is this project?

This is a **C# / .NET 8** diagnostic utility that captures raw hardware input directly from the Windows API (`User32.dll / Raw Input`) and applies real-time statistical analysis and machine learning heuristics to determine whether mouse movement is being generated by a **real physical peripheral** or by **artificial input injection / cheat automation**.

It outputs a live **suspicion score (0–100%)**, a **certainty score**, sub-scores for specific cheat vectors (Silent Aim, Triggerbot, Kinematic Jerk / Micro-Aim), a predicted verdict, and the top contributing factors. The classifier is an online logistic-regression model initialized with domain heuristics derived from anti-cheat research and fine-tuned locally on your PC via SGD feedback buttons.

The project conceptually simulates detection vectors used by commercial anti-cheat systems to detect:

- **Hardware mouse injectors** — **Macku**, **KM Box Net/Pro**, Arduino/Teensy HID spoofers, and Raspberry Pi Pico firmware
- **2PC / DMA setups** — secondary PC injecting movement vectors via network or USB pass-through
- **Silent aim & pSilent** — instantaneous snap to target hitbox followed by immediate sub-millisecond vector restoration to hide the flick from spectators
- **Triggerbots** — automated firing with unnatural reaction-time consistency and movement micro-pauses
- **Synthetic smoothing & recoil macros** — linear interpolation (LERP), bezier paths lacking biological micro-tremor, and axis-locked scripts
- **Modified firmware** delivering packets outside physical USB bus characteristics

### How does the detection work?

The key is measuring the **physical limits of human physiology and hardware signaling**.

In the real world, human neuromuscular motor control is bounded by muscle inertia, neural transmission latency (~100–200 ms), and involuntary physiological tremor (8–12 Hz). Concurrently, physical USB mice exhibit natural timing jitter and transfer characteristics. Anti-cheat systems exploit the mathematical discrepancy between biological movement and synthetic scripts:

| Characteristic | Real Physical Hardware & Human Hand | Software / Hardware Cheat Injection |
|---|---|---|
| Packet interval Δt | Slightly variable (e.g. 1.98ms, 2.01ms, 1.99ms) | Mathematically identical or zero-interval bursts (< 0.5ms) |
| Standard deviation (σ) | ≥ 0.06 ms (natural physical jitter) | ≤ 0.015 ms (inhuman clock precision) |
| Burst rate | < 10% even with aggressive physical movement | > 20% consistently during movement injection |
| Silent aim signature | Natural overshoot + delayed corrective submovement | Opposing return vector cancels snap in < 2.5ms |
| Triggerbot signature | Biological reaction-time variance (σ > 30ms) | Low-variance micro-pauses at fire events (CV < 0.05) |
| Kinematic acceleration | Smooth bell-shaped velocity profile, bounded acceleration | Step-function velocity jumps, impossible jerk (> 35 px/ms²) |
| Heading micro-tremor | Continuous angular adjustments (Δθ variance > 0.05 rad) | Zero angular deviation across consecutive packets (linear lock) |
| Model suspicion | Low suspicion score (< 45%) | High suspicion score (≥ 80%) |

### Implemented algorithm & 12 heuristic features

1. **Zero-overhead raw input capture:** The `WndProc` intercepts Win32 `WM_INPUT` messages using stack-allocated buffers (`stackalloc`, zero heap allocation) and high-resolution performance counters (`Stopwatch.ElapsedTicks`). Packets are enqueued in a lock-free `ConcurrentQueue`.

2. **Analysis thread:** A background thread drains packets, calculates interval deltas (Δt), velocity, acceleration, and heading deltas across a 100-packet rolling window.

3. **12 Extracted features (0.0 to 1.0):**
   - **Timing & Rate-Spoofing Injection (Features 0–5):**
     - `BurstRate`: Fraction of packets arriving in < 0.5 ms (physically impossible on standard USB bus).
     - `LowJitter`: Scale-invariant inverse coefficient of variation of Δt ($\sigma / \mu$).
     - `IntervalConcentration`: Share of intervals concentrated in the single most common 0.01 ms bucket.
     - `RepeatedIntervals`: Fraction of consecutive Δt identical at ~2 µs clock resolution.
     - `MovementUniformity`: Abnormally low variance in per-packet displacement magnitude.
     - `BurstClustering`: Longest consecutive run of burst packets.
   - **Silent Aim Detection (Features 6–7):**
     - `SilentAimSnapRate`: Frequency of large displacements ($\ge 20$ px) immediately reversed by an opposing vector within 2.5 ms.
     - `SilentAimReturnPrecision`: Dot-product cancellation ratio and magnitude match ($\ge 85\%$) of the return vector.
   - **Triggerbot Detection (Features 8–9):**
     - `TrigbotMicroPause`: Frequency of near-zero magnitude packets interrupting active movement (pausing movement during shot simulation).
     - `TrigbotPauseRegularity`: Abnormally low coefficient of variation of inter-pause intervals (clock-driven vs. biological reaction variance).
   - **Kinematics & Micro-Adjustments (Features 10–11):**
     - `KinematicJerk`: Instantaneous acceleration spikes ($|a| > 35\text{ px/ms}^2$) violating human neuromuscular inertia.
     - `MicroAdjustmentDeficiency`: Trajectory linearity / absence of physiological micro-tremor (runs of consecutive moving packets with $< 1.1^\circ$ heading variation).

4. **Online logistic-regression classifier:**
   - Evaluates $P(\text{injection}) = \text{sigmoid}(\text{bias} + \sum w_i \times f_i)$.
   - Outputs an overall **suspicion score (0–100%)**, a **certainty score**, sub-scores for **Silent Aim**, **Triggerbot**, and **Micro-Aim/Kinematics**, and human-readable top factors.
   - Threshold bands: **< 45% Likely Natural**, **45–80% Suspicious**, **≥ 80% Likely Injection**.

5. **Local online learning (SGD):**
   - Click **“✓ This is my real mouse”** or **“✗ This is injected”** to execute a stochastic gradient descent step on the current feature vector.
   - Weights persist locally to `%LOCALAPPDATA%\MousePollingMonitor\model.json`; **reset model** restores the research-backed heuristic prior.

6. **Visual dashboard:**
   - **Real-time Hz display** (instantaneous 1-second rolling count and window average)
   - **Sparkline** of the last 60 packets with burst indicators (red bars)
   - **Suspicion score bar** with certainty and sub-score cards
   - **Rolling event log** with timestamp, instant/average Hz, jitter ($\sigma$), burst rate, suspicion score, and verdict

### Research foundations

The heuristics and feature mappings in this engine are grounded in published anti-cheat research and human motor control literature:
- **Valve VACNet (GDC 2018):** View-angle delta sequences, reaction-time consistency profiling, and input synchronization.
- **BeCAPTCHA-Mouse (arXiv:2005.00890):** Kinematic modeling of mouse trajectories, velocity, acceleration, and jerk distributions.
- **Fitts's Law & Submovement Decomposition:** Human goal-directed aiming consists of a primary surge followed by corrective submovements (overshoot/undershoot with 100–250 ms feedback loop); cheats exhibit zero-overshoot or sub-millisecond cancellation.
- **Sigma-Lognormal Neuromotor Theory (Plamondon et al.):** Biological handstrokes decompose into overlapping lognormal velocity curves; linear interpolation and algorithmic smoothing violate neuromuscular timing constraints.

### O que é este projeto?

Este é um utilitário de diagnóstico em **C# / .NET 8** que captura dados brutos de entrada de hardware diretamente da API do Windows (`User32.dll / Raw Input`) e aplica análise estatística e heurísticas de machine learning em tempo real para determinar se o movimento do mouse está sendo gerado por um **periférico físico real** ou por **injeção artificial de input / trapaça automatizada**.

Ele calcula um **suspicion score ao vivo (0–100%)**, um **certainty score**, sub-scores para vetores específicos (Silent Aim, Triggerbot, Cinemática/Micro-ajustes), um veredito previsto e os principais fatores que contribuíram. O classificador é um modelo de regressão logística online inicializado com heurísticas de anti-cheat e ajustado localmente via botões de feedback com SGD.

O projeto simula conceitualmente vetores de detecção usados por anti-cheats comerciais para identificar:

- **Injetores de mouse por hardware** — **Macku**, **KM Box Net/Pro**, emuladores Arduino/Teensy e firmwares de Raspberry Pi Pico
- **Configurações 2PC / DMA** — PC secundário injetando vetores de movimento via rede ou USB pass-through
- **Silent aim & pSilent** — snap instantâneo para a hitbox seguido de restauração sub-milissegundo do vetor para ocultar a mira de espectadores
- **Triggerbots** — disparo automatizado com consistência de tempo de reação inumana e micro-pausas no movimento
- **Macros de suavização e recuo** — interpolação linear (LERP) e curvas bezier sem tremor biológico
- **Firmwares modificados** entregando pacotes fora dos limites físicos do barramento USB

### Como funciona a detecção?

A chave está em medir os **limites físicos da fisiologia humana e da sinalização de hardware**.

No mundo real, o controle motor humano é limitado por inércia muscular, latência de transmissão neural (~100–200 ms) e tremor fisiológico involuntário (8–12 Hz). Simultaneamente, mouses físicos USB possuem jitter natural de temporização. O sistema explora as diferenças matemáticas entre o movimento biológico e scripts sintéticos:

| Característica | Hardware Físico Real & Mão Humana | Injeção por Software / Hardware |
|---|---|---|
| Intervalo entre pacotes Δt | Ligeiramente variável (ex: 1.98ms, 2.01ms, 1.99ms) | Matematicamente idêntico ou rajadas com Δt < 0.5ms |
| Desvio padrão (σ) | ≥ 0.06 ms (jitter físico natural) | ≤ 0.015 ms (precisão inumana de clock) |
| Burst rate | < 10% mesmo em movimentos agressivos | > 20% consistentemente durante injeção |
| Silent aim | Overshoot natural + submovimento corretivo com atraso | Vetor oposto anula o snap em < 2.5ms |
| Triggerbot | Variação biológica do tempo de reação (σ > 30ms) | Micro-pausas com baixíssima variação (CV < 0.05) |
| Aceleração cinemática | Perfil suave de sino, aceleração contínua e limitada | Degraus instantâneos de velocidade, jerk impossível (> 35 px/ms²) |
| Micro-tremor angular | Micro-ajustes angulares contínuos (variância Δθ > 0.05 rad) | Desvio angular zero em pacotes consecutivos (trava linear) |
| Score do modelo | Suspicion score baixo (< 45%) | Suspicion score alto (≥ 80%) |

### Algoritmo implementado & 12 features heurísticas

1. **Captura de baixo nível sem heap:** O `WndProc` intercepta `WM_INPUT` com buffers alocados na pilha (`stackalloc`, zero alocação de heap) e cronômetros de hardware de alta precisão (`Stopwatch.ElapsedTicks`). Os pacotes são enfileirados em uma `ConcurrentQueue`.

2. **Thread de análise:** Uma thread em segundo plano consome os pacotes, calcula intervalos (Δt), velocidade, aceleração e variação de direção em uma janela deslizante de 100 pacotes.

3. **12 Features extraídas (0.0 a 1.0):**
   - **Temporização e Injeção USB (Features 0–5):**
     - `BurstRate`: Fração de pacotes chegando em < 0.5 ms.
     - `LowJitter`: Coeficiente de variação inverso de Δt ($\sigma / \mu$).
     - `IntervalConcentration`: Concentração de intervalos no bucket mais frequente de 0.01 ms.
     - `RepeatedIntervals`: Fração de Δt consecutivos idênticos na resolução de ~2 µs.
     - `MovementUniformity`: Baixa variação no deslocamento por pacote.
     - `BurstClustering`: Maior sequência consecutiva de pacotes em burst.
   - **Detecção de Silent Aim (Features 6–7):**
     - `SilentAimSnapRate`: Frequência de movimentos grandes ($\ge 20$ px) imediatamente revertidos em < 2.5 ms.
     - `SilentAimReturnPrecision`: Precisão do cancelamento por produto escalar e similaridade de magnitude ($\ge 85\%$).
   - **Detecção de Triggerbot (Features 8–9):**
     - `TrigbotMicroPause`: Frequência de pacotes de magnitude quase zero interrompendo movimento ativo.
     - `TrigbotPauseRegularity`: Baixo coeficiente de variação dos intervalos entre pausas (clock rígido vs. reação humana).
   - **Cinemática e Micro-Ajustes (Features 10–11):**
     - `KinematicJerk`: Picos de aceleração instantânea ($|a| > 35\text{ px/ms}^2$) violando inércia muscular.
     - `MicroAdjustmentDeficiency`: Ausência de micro-tremor fisiológico / interpolação linear perfeita ($< 1.1^\circ$ de variação).

4. **Classificador de regressão logística online:**
   - Calcula $P(\text{injeção}) = \text{sigmoid}(\text{bias} + \sum w_i \times f_i)$.
   - Gera um **suspicion score geral (0–100%)**, **certainty score**, sub-scores para **Silent Aim**, **Triggerbot** e **Micro-Aim/Cinemática**, e os principais fatores explicativos.
   - Faixas: **< 45% Provavelmente Natural**, **45–80% Suspeito**, **≥ 80% Provavelmente Injeção**.

5. **Aprendizado online local (SGD):**
   - Os botões de feedback executam um passo de gradiente descendente estocástico (SGD) no vetor atual.
   - Pesos salvos em `%LOCALAPPDATA%\MousePollingMonitor\model.json`; **reset model** restaura o prior heurístico.

## Architecture

```
WndProc [Main Thread — HOT PATH]
  └─ GetRawInputData (stackalloc, zero heap)
  └─ Stopwatch.ElapsedTicks  ← timestamp captured here
  └─ ConcurrentQueue.Enqueue

PacketProcessor [Background Thread]
  └─ Dequeue → Δt, velocity, acceleration, heading
  └─ Rolling window (100 samples)
       ├─ σ, coefficient of variation, burst rate
       ├─ interval concentration + repeated intervals
       ├─ movement uniformity + burst clustering
       ├─ silent aim snap-return tracker
       ├─ triggerbot micro-pause tracker
       ├─ kinematic jerk & micro-tremor analysis
       └─ Sparkline data
  └─ DetectionModel (online logistic regression, 12 features)
       ├─ P(injection) → suspicion score
       ├─ sub-scores: silent aim, triggerbot, kinematics
       ├─ certainty + top contributing factors
       └─ feedback → one SGD step → model.json
  └─ StatsUpdated → WPF dashboard

MainWindow [UI Thread]
  └─ Big Hz, stats row, sparkline
  └─ Suspicion score bar, verdict, sub-score cards
  └─ Rolling log & feedback buttons
```

## Tech stack

- **Language:** C# 12 / .NET 8
- **Platform:** Windows 10/11 x64 (Win32 Raw Input API)
- **UI:** WPF (dark dashboard)
- **Dependencies:** None (pure P/Invoke — zero external NuGet packages)
- **Capture:** `RegisterRawInputDevices` + `RIDEV_INPUTSINK` + `WM_INPUT`
- **Timing:** `System.Diagnostics.Stopwatch` (hardware performance counter)
- **Model:** Dependency-free online logistic regression (12 normalized features, SGD learning)
- **Persistence:** `System.Text.Json` → `%LOCALAPPDATA%\MousePollingMonitor\model.json`
